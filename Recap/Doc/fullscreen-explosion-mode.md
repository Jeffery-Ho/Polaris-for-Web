# 全屏选词模式

## 目标

- 在当前 AI 会话页面提供一个更像阅读稿面的全屏选词层，方便聚焦单段 assistant 正文后再复制。
- 保持现有 marker 导航逻辑不变，不新增独立页面或后台脚本。
- 正式覆盖当前扩展已支持的全部平台，而不是只按 ChatGPT 的标题结构工作。

## 交互

- 入口有两个：右侧控制区“爆炸模式”按钮，或 `Cmd/Ctrl+Shift+F`。
- 打开后即刻复用当前页面的 marker 结构，按标题切成多个 section。
- 弹层外部使用半透明 mask，正文收在约 `524pt` 宽的中等大小弹窗中，顶部保留“复制选中”“关闭”和横向 section chips；`Escape` 也可关闭。
- 关闭按钮需要明显区别于普通操作按钮，且弹窗整体需随系统亮/暗模式切换配色。
- 关闭时恢复页面滚动，不保留上一次选区。

## 内容范围

- 仅采集 `getAssistantContainers()` 已识别到的 AI 回复容器。
- 不包含用户输入框、网页侧边栏、按钮文案、设置菜单或扩展自身 DOM。
- 每个 section 以 `collectHeadings()` 产出的 marker 顺序为边界，支持原生标题、加粗独立标题、编号标题、无序列表标题、千问视频标题、元宝视频标题等现有 marker 来源。
- 正文优先按 `p`、`li`、标题、`pre` 等块级文本切段；块结构不稳定时回退到按双换行拆段。
- 弹窗正文默认展示“当前 section + 前一节 + 后一节”，当前 section 权重最高，相邻 section 弱化展示。

## 验证口径

- ChatGPT、豆包、Kimi、千问、元宝、小红书点点 AI 上都能打开爆炸模式。
- 任一平台存在 marker 时，顶部 chips 数量、顺序、标题与右侧 marker 一致。
- 多轮会话中，section 顺序和页面视觉顺序一致，顶部 chips 与正文区当前 section 高亮保持同步。
- 无序列表标题、编号标题、视频标题作为 marker 时，爆炸模式仍能正确切 section，不会吞掉后续整段正文。
- 选中文本时“复制选中”可用，未选中时按钮置灰。
- `Cmd/Ctrl+Shift+F` 在普通页面焦点下可打开；焦点在宿主输入框时不应误触发。
- Overlay 打开期间页面背景不可滚动，关闭后恢复。
